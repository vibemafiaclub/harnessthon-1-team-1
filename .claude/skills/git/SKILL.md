# 작업 저장

git을 몰라도 됩니다. 이 skill이 전부 처리합니다.

## 절차

### 1. 변경 내용 파악

```bash
git status --porcelain
git diff
git diff --cached
```

### 2. 한 문장으로 요약

이번 작업에서 무엇을 했는지 **한 문장**으로 요약합니다.
파일 목록 나열이 아니라 **무엇이 좋아졌는지**를 씁니다.

- ❌ "stage-2-tokens.md 수정"
- ✅ "컬러 토큰 단계가 브랜드 컬러의 명도 단계를 스스로 만들도록 개선"

### 3. 사용자에게 확인 (필수)

요약 문장을 보여주고 **반드시** 이렇게 묻습니다:

> 이 문장으로 하면 될까요? 아니면 조금 뉘앙스를 바꾸면 좋을만한 부분이 있을까요?

사용자가 확정한 문장을 그대로 **commit message**로 씁니다.
확인 없이 커밋하지 않습니다.

### 4. 커밋

```bash
git add -A
git commit -m "{확정된 문장}"
```

### 5. 푸시 — 브랜치는 main만 씁니다

```bash
git push origin main
```

**성공하면 여기서 끝입니다.**

### 6. push가 거부되면 (다른 사람이 먼저 올림)

rebase로 조치합니다.

```bash
git pull --rebase origin main
```

**rebase가 깔끔하게 끝났으면** 다시 push하고 끝냅니다.

```bash
git push origin main
```

### 7. conflict가 발생했다면

**같은 파일을 두 사람이 고쳤다는 뜻입니다.** 먼저 이 문구를 그대로 보여주세요:

> **작업 충돌이 발생했습니다. 이후부터는 조장과 동행해서 진행하세요.**

그 다음 사용자와 대화하며 충돌을 해결합니다:

1. 충돌 파일과 충돌 구간을 **사람이 읽을 수 있는 말로** 설명합니다
   ("내 쪽은 A로 바꿨는데, 먼저 올라온 쪽은 B로 바꿨습니다")
2. 어느 쪽을 살릴지, 혹은 둘 다 살릴지 **사용자에게 묻습니다**
3. 결정대로 파일을 고칩니다
4. `git add {파일}` → `git rebase --continue`
5. 남은 충돌이 있으면 1번으로 돌아갑니다
6. **`git push origin main`까지 완료**하고 끝냅니다

## 왜 충돌이 났을까 (사용자에게 알려줄 것)

이 레포는 **"내가 맡은 단계만 수정한다"**는 규칙으로 충돌을 막고 있습니다.
충돌이 났다는 것은 **그 규칙이 어딘가에서 깨졌다**는 신호입니다.

- 남이 맡은 단계 파일을 건드리지 않았는지
- 공용 파일(`AGENTS.md`, `start/SKILL.md`)을 조장 승인 없이 고치지 않았는지

확인하고, 조장과 함께 정리하세요.

## 금지

- `main` 외의 브랜치 생성
- `git push --force` (어떤 경우에도)
- 사용자 확인 없는 커밋
