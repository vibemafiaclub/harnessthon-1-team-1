# 8단계 — 독립 비평 (Fresh Critic)

> 담당자: TBD
>
> **너는 제작자가 아니다.** 7단계가 무엇을 의도했는지 묻지 않는다.
> PRD·레퍼런스·실제 Penpot 결과만 보고 판단한다.
> **이 단계는 디자인을 고치지 않는다.** 고치는 것은 9단계다. 여기서는 **Finding만 남긴다.**

## 입력 (이것만 읽는다)

- `docs/PRD.md` — 요구사항의 기준
- `docs/artifacts/01-screens.md` — 요구 화면 목록
- `docs/artifacts/02-existing-assets.md` — 레퍼런스의 실측 시각 규칙
- `docs/artifacts/04-design-guide.md` — 토큰·컴포넌트 스펙
- `docs/design-copy-rules.md` — 카피·표기 규칙 (AI티 검사 기준)
- Penpot 실제 화면 — **읽기 전용**
- 인자: **작업 Page 이름**, `run-id`

> **07-screens.md 는 읽지 않는다.** 제작자의 자기 보고를 근거로 삼으면 비평이 아니다.
> 무엇이 만들어졌는지는 Penpot에서 직접 읽는다.

## 출력 (이것만 쓴다)

- `docs/artifacts/08-findings.md`

## 🔴 Page 규칙

- 작업 Page 이름을 못 받았으면 **비평하지 않는다.** 묻는다. 엉뚱한 Page를 보고 채점하면 멀쩡한 작업을 망친다.
- **읽기만 한다. 아무것도 만들거나 고치지 않는다.** Page 전환도 하지 않는다.
- 비평 중에는 7단계가 저작을 멈춰야 한다. 평가 대상 버전이 바뀌면 Finding과 증거가 어긋난다.

## 절차

1. 입력을 읽는다. 없으면 **즉시 중단하고 보고한다.**
2. 각 화면을 `export_shape` 로 **PNG로 본다.** 빈 이미지면 재-export 한 번. 노드 속성만 읽고 채점하지 않는다.
   **화면을 보지 않고 쓴 Finding은 무효다.**
3. **A. 5축 채점** — 아래 rubric으로 화면마다 1~5점. 점수마다 **근거가 되는 화면·요소**를 적는다.
4. **B. 닐슨 휴리스틱 10원칙** — 위반만 적는다. 해당 없으면 `N/A`.
5. **C. AI티 검사** — `docs/design-copy-rules.md` 의 검사표를 **세어서** 채운다.
6. 발견한 것을 **Finding 형식**으로 정리한다. severity와 **원인 단계(owner stage)** 를 반드시 지정한다.
7. 출력 파일을 쓴다.

---

## A. 5축 채점 rubric

각 축은 **화면별 점수**와 **전체 점수**(최저 화면 기준, 평균 아님)를 낸다.
평균을 내면 한 화면이 무너져도 가려진다. **최저값이 그 하네스의 실력이다.**

### A-1. 위계 설정 / 강약조절

| 점수 | 기준 |
|---|---|
| 1 | 모든 요소가 같은 크기·굵기·색. 어디를 먼저 볼지 알 수 없다 |
| 2 | 제목/본문 구분만 있다. 화면의 1차 액션이 눈에 띄지 않는다 |
| 3 | 위계는 있으나 **강조가 3개 이상 경합**한다. 시선이 분산된다 |
| 4 | 1차 정보가 즉시 읽히고 2·3차가 물러나 있다. 일부 화면에서 흔들린다 |
| 5 | 모든 화면에서 시선 순서가 의도대로. **화면당 강조는 1개**. 대비를 크기·굵기·색·여백 중 **2개 이상 조합**으로 만든다 |

**관찰 방법**: 화면 PNG를 보고 **가장 먼저 눈에 들어온 요소**를 적는다.
그게 그 화면의 목적(01의 "목적" 열)과 다르면 3점 이하다.

### A-2. 유저 고려 일치도

| 점수 | 기준 |
|---|---|
| 1 | PRD가 말한 사용자가 이 화면에서 무엇을 할지 알 수 없다 |
| 2 | 기능은 있으나 대상 사용자의 숙련도를 무시한다 (초보 대상인데 전문용어·고밀도) |
| 3 | 주 사용자는 고려됐으나 **PRD가 명시한 다른 유형**(빈 상태·미설정·과다 데이터)이 빠져 있다 |
| 4 | 사용자 유형별 경로가 있다. 일부 상태가 얕다 |
| 5 | PRD 사용자 상황 절의 **모든 유형**이 화면으로 존재하고, 각 유형이 다음에 할 일이 화면 안에 있다 |

**관찰 방법**: PRD 사용자 상황 절의 문장을 하나씩 들고 "이 사람이 이 화면에서 막히나"를 본다.

### A-3. 서비스 기획 방향 일치도

| 점수 | 기준 |
|---|---|
| 1 | PRD 배경·목표와 반대 방향이다 |
| 2 | 요구 기능은 있으나 **PRD가 피하려던 것**을 그대로 한다 |
| 3 | 방향은 맞으나 **무엇을 위로 올릴지**의 판단이 안 보인다. 요소를 나열만 했다 |
| 4 | 우선순위 판단이 보인다. 일부 화면에서 흔들린다 |
| 5 | PRD의 핵심 주장이 **화면 구조 자체로** 드러난다. 무엇을 뺐는지도 설명된다 |

**관찰 방법**: PRD 1절(배경)의 문제 정의를 읽고, 그 문제가 이 화면에서 실제로 해결되는지 본다.

### A-4. 레퍼런스 서비스다움 (브랜드 진정성)

> ⚠️ 특정 회사 이름을 기준에 박지 않는다. 기준은 **`02-existing-assets.md` 가 실측한 그 제품**이다.
> 심사용 PRD의 레퍼런스는 미공개다.

| 점수 | 기준 |
|---|---|
| 1 | 레퍼런스와 무관한 화면. 범용 템플릿처럼 보인다 |
| 2 | 색만 비슷하다. 구조·밀도·말투가 다르다 |
| 3 | 색과 폰트는 맞으나 **밀도(정보량·여백)** 나 **컴포넌트 생김새**가 다르다 |
| 4 | 로고를 가려도 같은 제품군으로 보인다. 세부에서 어긋난다 |
| 5 | **로고를 가려도 그 회사가 만든 것으로 보인다.** 토큰·컴포넌트 구조·밀도·말투가 02의 실측과 일치한다 |

**관찰 방법**: 02의 색·타이포·간격 빈도표와 신규 화면의 실제 값을 **대조한다.**
"느낌이 비슷하다"는 근거가 아니다. **값이 근거다.**

### A-5. 기본 완성도 (줄바꿈·간격)

| 점수 | 기준 |
|---|---|
| 1 | 텍스트가 잘리거나 요소가 겹친다 |
| 2 | 잘림은 없으나 간격이 제각각이다 (비토큰 값 다수) |
| 3 | 대체로 정렬됐으나 **어색한 줄바꿈**이나 정렬 이탈이 눈에 띈다 |
| 4 | 정렬·간격이 일관적이다. 1~2곳 미세 이탈 |
| 5 | 모든 간격이 토큰 값이고, 줄바꿈이 자연스럽고, 좌우 여백이 화면 전체에서 일치한다 |

**관찰 방법 (반드시 실측한다)**
- 잘린 텍스트: `growType === "auto-height"` 인데 높이가 내용보다 작은 노드
- 비토큰 간격: 형제 노드 간 gap이 04의 `space` 스케일에 없는 값
- 좌우 여백 불일치: 각 화면 최상위 자식들의 `x` 값 분산

## B. 닐슨 휴리스틱 10원칙 (위반만 적는다)

| # | 원칙 | 이 화면에서 볼 것 |
|---|---|---|
| 1 | 시스템 상태 가시성 | 로딩·진행·처리중 상태가 화면으로 있는가 |
| 2 | 현실세계와의 일치 | 전문용어 대신 사용자 언어인가. 순서가 논리적인가 |
| 3 | 사용자 제어권과 자유 | 뒤로·취소·되돌리기 출구가 있는가 (특히 시트·모달) |
| 4 | 일관성과 표준 | 같은 액션이 화면마다 같은 위치·같은 이름인가 |
| 5 | 에러 방지 | 잘못 누를 수 있는 구조인가. 확인 단계가 있는가 |
| 6 | 기억보다 인지 | 앞 화면에서 본 것을 기억해야 진행되는가 |
| 7 | 유연성·효율성 | 숙련 사용자의 지름길이 있는가 |
| 8 | 미니멀 디자인 | 이 화면에서 **뺄 수 있는 요소**가 있는가 |
| 9 | 에러 복구 도움 | 에러 화면이 원인과 다음 행동을 말하는가 |
| 10 | 도움말·문서 | 처음 쓰는 사용자를 위한 안내 진입점이 있는가 |

각 위반은 Finding으로 등록한다. **원칙 번호를 Finding에 적는다.**

## C. AI티 검사

`docs/design-copy-rules.md` 의 검사표를 화면마다 채운다. **세어서 숫자로 적는다.**
이모지 ≥1개 또는 자리표시자 ≥1개는 **MAJOR**. 나머지 위반은 **MINOR**.

---

## Finding 형식 (이 형식으로만 적는다)

```yaml
id: F-003
run: run-02
source: ai                      # ai | human
severity: MAJOR                 # BLOCKER | MAJOR | MINOR
axis: A-4 레퍼런스다움           # 또는 N-08(닐슨), C-이모지
where: "New/Discover / 추천 카드 / 배지"
observed: "02 실측은 강조색 1개인데 결과는 3색 그라디언트"
evidence: "02 색 빈도표 상위 3개 vs 해당 노드 fills 값"
why: "레퍼런스의 절제된 밀도가 사라져 범용 핀테크처럼 보임"
fix: "04 토큰의 brand 단일색으로 교체, 강조 요소를 화면당 1개로 축소"
owner_stage: stage-4-design-guide   # 이 문제를 만든 단계
acceptance:
  - "새 색상 추가 없음"
  - "화면당 강조 요소 1개"
status: open                    # open | needs_recheck | resolved | still_failing | regression | duplicate
```

**severity 기준**
- `BLOCKER` — 화면이 없다 / 텍스트가 잘렸다 / 요소가 겹쳤다 / 자리표시자가 남았다 / PRD 필수 요소 누락
- `MAJOR` — 5축 중 하나가 2점 이하 / 이모지 / 닐슨 위반 중 사용자가 막히는 것
- `MINOR` — 4~5점을 방해하는 세부

**owner_stage 를 반드시 지정한다.** 화면을 직접 고치라고 쓰지 않는다.
같은 실수가 다음 실행에서 반복되지 않으려면 **문제를 만든 단계**가 고쳐져야 한다.

| 증상 | owner_stage |
|---|---|
| 색·간격·타이포가 레퍼런스와 다름 | `stage-4-design-guide` (근거가 02에 없으면 `stage-2`) |
| 화면·상태가 아예 없음 | `stage-1-prd-screens` |
| 요소는 있는데 배치·위계가 나쁨 | `stage-5-html-prototype` |
| 잘림·겹침·비토큰 간격 | `stage-7-penpot-screens` |
| 컴포넌트가 없거나 인스턴스가 아님 | `stage-6-penpot-library` |
| 카피가 AI티 남 | `stage-5` (문안) 또는 `stage-7` (반영) |

## 금지

- **디자인을 고치지 않는다.** Penpot에 쓰지 않는다. Finding만 남긴다.
- `07-screens.md` 를 근거로 삼지 않는다. Penpot 실물과 PNG만 근거다.
- 화면을 보지 않고 채점하지 않는다. **PNG를 안 봤으면 점수를 쓰지 않는다.**
- "느낌이 안 산다" 같은 근거 없는 Finding 금지. **02의 실측값·개수·좌표**로 말한다.
- 점수를 평균 내지 않는다. **최저 화면이 그 축의 점수다.**
- 특정 회사 이름을 rubric에 박지 않는다. 레퍼런스는 02가 실측한 제품이다.
- 다른 단계의 출력 파일을 쓰지 않는다.
