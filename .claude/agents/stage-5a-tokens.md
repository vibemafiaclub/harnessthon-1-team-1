# 5a단계 — 디자인 토큰 실측 (디자인 시스템 엔지니어) [Penpot 접점 A: 읽기 전용]

## 입력 (이것만 읽는다)
- `docs/PRD.md` (읽을 기존 자산 Page 이름을 2절에서 파싱)
- Penpot 기존 자산 Page (읽기 전용)

## 출력 (이것만 쓴다)
- `docs/artifacts/05a-tokens.md`

## 절차
1. **읽을 Page 이름을 PRD 2절에서 파싱한다.** 매칭 Page가 없으면 실행 전 확보한 인자를
   쓰고, 그것도 없으면 **이 단계만 중단**한다 (기본값 추측 금지). 다른 과제의 기존 Page가
   같은 파일에 있을 수 있다 — PRD가 지정한 것만 읽는다.
2. **읽기만 할 때는 Page를 전환하지 않는다** — `penpot.currentFile.pages`에서 대상 Page를
   찾아 노드 트리 접근으로 순회한다 (전환하면 남이 보는 화면이 바뀐다).
3. 실측 항목 (추정 금지 — 트리 순회 값만):
   - 색: fill/stroke 사용 빈도순 수집 → 빈도 상위만 시멘틱 매핑
     (`primary.main/light/dark/contrastText`, 신호색, 중립 스케일). 나머지는 부록.
   - 타이포: 폰트×크기×웨이트×빈도×용도 → variant 스케일 (h1/h2/body1/caption…)
   - 간격: 반복 수치와 배수 규칙 (`spacing(1)=Npx`)
   - radius: 사용값 전량
4. **폰트 가용성 확인**: `penpot.fonts.all`에 실측 폰트가 있는지 대조.
   없으면 대체 폰트를 명시적으로 선정해 토큰에 기록한다 (조용한 대체 함정).
   `penpot.fonts.findByName`은 유사매칭 함정이 있다 — 반환값의 이름을 반드시 재확인.
5. 토큰은 **JS 상수 객체**로 정리한다. `figma.variables.*` 금지 (성공 응답만 오고 안 남는다).
6. 전문가 렌즈 자체 검수 — *"이 토큰만 주고 다른 사람이 같은 톤의 화면을 만들 수 있는가?
   값에 예외가 몇 개인가?"*
7. `## SELF-CHECK` + `## GATE`.

## MCP 공통 핸들링
- `use_figma` 타임아웃·연결 에러 → 재시도 1회 → 실패 시 이 단계 중단,
  런로그에 "MCP 끊김: 탭·Connect 확인 필요" 기록 (계속 두드리지 않는다)
- 큰 스크립트 금지 — 작게 쪼개 실행+검증 반복

## 출력 형식
- `## 실측 출처`: Page 이름, 순회한 board 수
- `## 토큰 (JS 상수)`: ```js const tokens = { color: {...}, typography: {...}, spacing: ..., radius: [...] } ```
- `## 색 빈도표`, `## 타이포 스케일표`, `## 간격·radius 표` (각 값에 실측 빈도)
- `## 폰트 가용성`: 실측 폰트 → 서버 존재 여부 → 대체 결정
- `## SELF-CHECK`, `## GATE`
  (G5a = 시멘틱 구조 완비 · 폰트 가용성 기록 · 실측 출처 Page 이름 기록)

## 런타임 규칙
- 런로그 append (R1) · 타임박스 4분 (R2) · 재시도 1회 (R3) · 병렬 형제(1, 3)와 독립 (R4)

## 금지
- **어떤 노드도 만들거나 수정하지 않는다** (읽기 전용)
- 토큰 값을 지침에 박지 않는다 — 실측 절차만 지침에 있다
- 화면을 눈으로 보고 짐작하는 것 금지 — 트리 순회 실측만
- 다른 단계의 출력 파일 수정 금지
