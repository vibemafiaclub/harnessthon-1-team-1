# 1단계 — PRD → 화면 요구사항 추출

> 담당자: TBD

## 입력 (이것만 읽는다)

- `docs/PRD.md`

## 출력 (이것만 쓴다)

- `docs/artifacts/01-screens.md`

## 절차

1. `docs/PRD.md` 를 **전문** 읽는다. 파일이 없거나 비어 있으면 **즉시 중단하고 보고한다.**
2. 화면을 **세 군데**에서 뽑는다. 한 군데라도 빠지면 이 단계는 실패다.
   - **(a) 필수 화면을 명시한 절** — 화면 이름·목적·필수 요소가 직접 적혀 있는 곳
   - **(b) 유저 스토리 절** — 문장마다 아래 환원 규칙을 적용한다
   - **(c) 사용자 상황·엣지케이스 절** — 빈 상태·로딩·실패·과다 데이터는 **각각 화면 1개**다
3. 유저 스토리 환원 규칙 (문장 → 화면)

   | PRD 문장 패턴 | 나와야 하는 화면 |
   |---|---|
   | "…하고 **그 결과를 확인**하고 싶다" | 실행 화면 + **결과 화면** (2개) |
   | "**진입점**" 이 필수 요소로 적힌 경우 | 그 진입점을 눌렀을 때의 **목적지 화면 또는 시트** |
   | "정렬 / 필터" | 정렬·필터 **시트 또는 패널** |
   | "…을 **입력**해 …한다" | 입력 폼 + **검증 실패 상태** |
   | "아직 아무것도 …하지 않은 사용자" | 해당 화면의 **빈 상태** |
   | "데이터가 아직 안 들어오는" / "느린" | **로딩·스켈레톤 상태** |
   | "실패하는 경우가 있다" | **에러 상태 / 에러 다이얼로그** |
   | "많게는 N개까지" | 목록 화면의 **대량 데이터 스크롤 상태** |

4. **화면 개수를 미리 정하지 않는다.** PRD가 "최소 N개"라고 적었어도 그건 하한선이다.
   2~4번 절차에서 나온 것을 전부 적고, 우선순위(P0/P1/P2)로 순서만 매긴다.
   - **폭주 가드**: 화면(상태 변형 제외)이 20개를 넘으면 각 화면에 IA 킬러 질문을 던진다 —
     *"이 화면을 지우면 PRD의 어떤 문장이 끊기는가?"* 답 못하는 화면은 P2로 강등한다.
     저작 단계는 P0→P1→P2 순서로 만들다 시간이 끊기므로, 여기서 순서가 곧 생존 순서다.
5. **네이밍 규칙은 PRD에서 읽는다.** PRD가 제출 절에서 프레임 이름 규칙(접두사 등)을
   지정했으면 그 규칙을 그대로 화면 ID에 적용한다. 지정이 없으면 `Screen/PascalCase` 로 한다.
6. **커버리지 검사**: PRD의 유저 스토리 절·사용자 상황 절의 **모든 문장**을 표로 늘어놓고
   각 문장이 어느 화면에 매핑되는지 적는다. **미매핑 0이 될 때까지 화면을 추가한다.**
7. **포지션 문장 1개를 뽑는다.** PRD 배경 절에서 "모회사가 이 도메인에 가져오는 관점"을
   한 문장으로 고정한다 (예 형식: "{모회사}가 {기존 문법}으로 {기존 불편}을 없앴듯,
   이 서비스는 {같은 문법}으로 {새 도메인의 불편}을 없앤다"). 이 문장이 없으면 뒤 단계가
   경쟁사 화면을 그대로 복사해 포지션이 실종된다 — 리허설에서 실증된 드리프트다.
   회사명·도메인명을 이 지침에 박지 않는다. 매번 PRD에서 도출한다.
8. 출력 파일을 쓴다.

## 출력 형식

````markdown
# 01 — 화면 요구사항

> 포지션: {한 문장 — 모회사의 문법을 이 도메인에 어떻게 이식하는가. 뒤 단계 전부의 기준}

## 제품 요약
- 도메인: {PRD에서 읽은 제품 카테고리}
- 대상 사용자: {PRD 인용}
- 기존 자산 Page 이름: {PRD 기존 자산 절에 적힌 Page 이름 — 없으면 "PRD 미기재"}
- 프레임 네이밍 규칙: {PRD 제출 절에서 읽은 규칙}

## 화면 목록

| ID | 화면 이름 | 유형 | 목적 | 필수 요소 | 근거(PRD 위치) | 우선순위 | 부모 화면 |
|---|---|---|---|---|---|---|---|
| S01 | New/Xxx | 화면 | … | 요소1 / 요소2 | 6-1절 | P0 | - |
| S02 | New/Xxx/OrderSheet | 시트 | … | … | 6-2절 필수요소 | P0 | S01 |

- 유형: `화면` / `시트` / `모달` / `상태변형`
- 부모 화면: 시트·모달·상태변형은 어느 화면 위에 올라오는지 반드시 적는다

## 상태 변형

| 상위 화면 | 상태 | 트리거 | 화면에 보여야 할 것 | 근거 |
|---|---|---|---|---|
| S01 | 빈 상태 | 담은 항목 0개 | … | 5절 |
| S01 | 로딩 | 시세 미수신 | … | 5절 |

## 커버리지 매핑 (미매핑 0이어야 한다)

| PRD 문장 | 절 | 매핑 화면 ID |
|---|---|---|
| "…" | 3-1 | S01, S03 |

**미매핑 문장: 0건** ← 0이 아니면 이 단계는 미완료다.

## 데이터 요건 (다음 단계가 더미 콘텐츠를 만들 때 쓴다)

| 화면 ID | 리스트/필드 | 현실적인 행 수 | 값의 성격 |
|---|---|---|---|

## 미해결 질문
- PRD만으로 결정할 수 없는 것들 (다음 단계가 가정으로 채울 지점)
````

## 금지

- **PRD에 없는 화면을 지어내지 않는다.** 모든 행에 근거 위치가 있어야 한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다. 고유명사·고정 화면 개수·
  고정 화면 이름을 이 파일의 지침이나 출력 템플릿에 박지 않는다. 전부 PRD에서 읽는다.
- Penpot을 건드리지 않는다. 이 단계는 문서만 만든다.
- 다른 단계의 출력 파일을 쓰지 않는다.
