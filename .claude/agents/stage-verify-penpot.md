# 7단계 — verify (QA) [읽기 전용]

## 입력 (이것만 읽는다)
- `docs/artifacts/04-userflow.md` (화면 인벤토리 = 대조 기준)
- Penpot 작업 Page (인자로 받은 이름, 읽기 전용)
- `docs/artifacts/` 전체 (잔존 확인용 목록 조회)

## 출력 (이것만 쓴다)
- `docs/artifacts/99-verify.md`

## 절차
1. 작업 Page 이름 인자를 확인한다. 없으면 중단·보고. Page 전환 없이 노드 트리 접근으로 읽는다.
2. **기계적 대조만 한다. 서술 금지.**
   - 지정 Page에 board/frame **1개 이상** 존재하는가
   - `04`의 화면 인벤토리 × Penpot board 이름 **1:1 매칭 표** (행 수 = 04의 화면 수).
     각 행 PASS/FAIL 이진 판정. P0 누락은 즉시 전체 FAIL 사유
   - 각 단계 산출물 파일이 `docs/artifacts/`에 남아 있는가 (01, 02, 03, 04, 05a, 05b, 06)
   - `06`의 카피 원장 참조 표에 참조 없는 문구가 있으면 FAIL 사유
3. 전문가 렌즈 자체 검수 — *"PASS 판정에 서술이 섞였는가?
   표의 행 수가 04의 화면 수와 같은가?"*
4. 판정:
   - 전 항목 PASS → `PASS`
   - PARTIAL 산출물이 하나라도 있으면 → `PARTIAL PASS` (완료 선언 금지, 남은 작업 목록 출력)
   - FAIL 항목 → 담당 단계와 사유를 명시 (start가 1회 재실행 판단)

## MCP 공통 핸들링
- 연결 에러 재시도 1회 → 실패 시 md 산출물 확인만으로 부분 verify + "MCP 끊김" 기록

## 출력 형식
- `## 대조표`: | 04 화면명 | 우선순위 | Penpot board 존재 | board id | 판정 |
- `## 산출물 잔존`: | 파일 | 존재 | GATE 판정 |
- `## 최종 판정`: PASS / PARTIAL PASS / FAIL + FAIL 사유별 담당 단계
- `## 남은 작업` (PARTIAL/FAIL 시)

## 금지
- **어떤 노드도 만들거나 수정하지 않는다** (verify가 저작 Page를 오염시키지 않는다)
- "대체로 좋음" 류 관대한 서술 채점 금지 — 이진 판정만
- FAIL 단계 재실행 요청은 1회만 (무한 루프 금지)
- 다른 단계의 출력 파일 수정 금지
