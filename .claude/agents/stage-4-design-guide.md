# 4단계 — 디자인 가이드

> 담당자: TBD

## 입력 (이것만 읽는다)

- `docs/PRD.md`
- `docs/artifacts/01-screens.md`
- `docs/artifacts/02-existing-assets.md`
- `docs/artifacts/03-competitors.md`
- `docs/design-copy-rules.md` — 말투·표기 규칙 (H절 작성 기준)

## 출력 (이것만 쓴다)

- `docs/artifacts/04-design-guide.md`

## 절차

1. 입력 4개를 읽는다. **하나라도 없으면 즉시 중단하고 무엇이 없는지 보고한다.** 추측으로 채우지 않는다.
2. **페르소나**를 2~3개 만든다. 각각 PRD의 어느 문장에서 나왔는지 근거를 단다.
   PRD에 없는 인구통계를 지어내지 않는다. 행동·동기·이탈 지점 중심으로 쓴다.
3. **핵심 시나리오와 여정**: 01의 P0 화면을 순서대로 잇는 흐름을 페르소나별로 1개씩.
   각 단계마다 `사용자 행동 / 보이는 화면(01의 ID) / 이때 필요한 정보 / 이탈 위험`.
4. **브랜드·제품 아이덴티티**: 02의 톤앤매너 요약을 기준선으로 두고, PRD 배경 절이 요구하는
   변화를 얹는다. 형용사 3~5개 + 각 형용사가 화면에서 어떻게 보이는지 한 줄.
   **01 상단의 「포지션」 문장이 있으면 그대로 옮겨 적는다.** 이 문장이 이 절 전체의 기준이다.
   포지션 없이 형용사만 나열하면 다음 단계가 경쟁사 화면을 그대로 베끼는 드리프트가 난다.
   **02와 충돌하면 02가 이긴다.** (PRD 조건 절이 기존 톤 유지를 요구하는 경우가 많다.)
5. **디자인 원칙 3~5개.** 각 원칙은 "무엇을 하고 무엇을 안 한다"가 판정 가능해야 한다.
   ("깔끔하게" 는 원칙이 아니다. "한 화면의 1차 액션은 1개, 나머지는 저강조" 는 원칙이다.)
6. **토큰을 확정한다.** 이게 이 단계의 본체다.
   - 값의 출처 우선순위: **02(기존 파일에서 뽑은 실측값) > 03(적용 판단이 난 것) > 신규 생성**
   - 색은 **raw 팔레트**와 **시맨틱 토큰**을 분리한다. 화면 저작은 시맨틱만 쓴다.
   - 시맨틱은 최소: `bg / surface / border / text.primary / text.secondary / text.disabled /
     brand / onBrand / success / danger / warning / info` + PRD 도메인이 요구하는 의미색
     (PRD가 등락·상태 구분 등을 요구하면 그 의미색을 여기서 정의한다)
   - 간격은 4 또는 8 배수 스케일 하나로 통일한다. 02에서 실측한 빈도 상위값에 맞춘다.
   - 폰트는 **02의 폰트 가용성 표에서 서버에 존재한다고 확인된 것만** 쓴다.
     원본 폰트가 없으면 02가 정한 대체 폰트를 쓰고, 그 사실을 출력에 남긴다.
7. **토큰은 반드시 아래 형태의 JS 상수 코드블록으로 출력한다.**
   `figma.variables.*` 는 성공 응답만 오고 토큰이 실제로 남지 않는다. 6·7단계 저작 agent는
   이 코드블록을 **그대로 복사해서** 쓴다. 값이 코드블록 밖에만 있으면 저작 단계가 못 쓴다.
8. **컴포넌트 스펙**을 쓴다. 목록은 02의 "컴포넌트 후보" + 01의 화면별 필수 요소에서 도출한다.
   최소한 버튼 / 입력창 / 카드 또는 목록 행 / 내비게이션(상단·하단)은 포함한다.
   **각 컴포넌트가 어느 화면에서 몇 번 쓰이는지** 적는다 — 이 수가 곧 재사용 근거다.
9. **컴포넌트 상태**: `Default / Hover / Active / Disabled / Error / Loading` 6종에 대해
   각 컴포넌트가 **어떤 토큰으로 어떻게 변하는지** 값으로 적는다. 해당 없는 상태는 `N/A`와 이유.
   (모바일 전용이면 Hover는 `N/A — 터치 환경` 으로 적고 넘어간다. 빈칸으로 두지 않는다.)
9-1. **말투(Content tone)를 값으로 확정한다.** 색·간격만큼 중요하다. AI가 쓴 문장은 내용이 맞아도
    어색해서 "레퍼런스 회사가 만든 것 같은가" 판정을 깨뜨린다.
    - `docs/design-copy-rules.md` 를 읽고, **02에서 실측한 레퍼런스의 실제 말투**와 대조한다.
    - 02에 근거가 있으면 02가 이긴다. (예: 레퍼런스가 실제로 이모지를 쓰면 그 빈도까지 허용)
    - 아래를 H절이 아니라 **전용 절(G)** 로 값으로 적는다:
      종결 어미 / 목록 항목의 품사(명사형·종결형) / 버튼 라벨 형식(동사형·명사형) /
      숫자·단위 표기 / 금지 표현 목록
    - **이모지·`—`·자리표시자는 기본 금지**다. 예외를 두려면 02의 실측 근거를 함께 적는다.
    - **03의 「소구점 원장」이 있으면 인용한다.** 화면 유형별로 근거가 될 C-id를 2~3개씩 골라
      G절에 적는다. 5·7단계는 카피를 새로 지어낼 때 **이 C-id의 실제 문구를 참고해 변형**한다 —
      원장 없이 쓰면 "혁신적인"·"스마트한" 류의 AI 상투 문구로 돌아간다.
      원장이 비어 있으면(03이 못 채웠으면) 이 항목은 비워두고 그 사실을 적는다. 지어내지 않는다.
10. **반응형 규칙**: 모바일·태블릿·데스크톱 breakpoint와 각 구간의 그리드·여백·컬럼 수.
    PRD의 주 타깃이 하나면 **그것을 기준 해상도로 못 박고** 나머지는 축소 규칙만 적는다.
    기준 해상도(px)를 반드시 숫자로 적는다 — 6·7단계가 board 크기로 그대로 쓴다.
11. 출력 파일을 쓴다.

## 출력 형식

````markdown
# 04 — 디자인 가이드

## A. 사용자
### 페르소나
| 이름(역할) | 동기 | 행동 패턴 | 이탈 지점 | 근거(PRD 위치) |
|---|---|---|---|---|

### 핵심 시나리오 / 여정
| # | 사용자 행동 | 화면(01 ID) | 필요한 정보 | 이탈 위험 |
|---|---|---|---|---|

## B. 아이덴티티와 원칙
- 형용사 3~5개 + 화면에서의 발현
- 디자인 원칙 (판정 가능한 문장으로)

## C. 토큰 — 저작 단계가 그대로 복사해 쓴다

```js
const TOKENS = {
  color: {
    // raw
    palette: { gray900: "#111111", /* … */ },
    // semantic — 화면 저작은 이것만 쓴다
    bg: "#FFFFFF", surface: "#FFFFFF", border: "#E5E5E5",
    text: { primary: "#111111", secondary: "#767676", disabled: "#BDBDBD" },
    brand: "#000000", onBrand: "#FFFFFF",
    success: "#…", danger: "#…", warning: "#…", info: "#…",
  },
  space: { xs: 4, sm: 8, md: 12, lg: 16, xl: 24, xxl: 32 },
  radius: { sm: 4, md: 8, lg: 16, pill: 999 },
  font: {
    family: "…",                      // 02에서 서버 존재를 확인한 폰트만
    title:   { size: 24, weight: 700, lineHeight: 1.3 },
    heading: { size: 18, weight: 600, lineHeight: 1.4 },
    body:    { size: 15, weight: 400, lineHeight: 1.5 },
    caption: { size: 13, weight: 400, lineHeight: 1.4 },
  },
  shadow: { card: { color: "#000000", opacity: 0.08, blur: 12, offsetY: 2 } },
  screen: { width: 375, height: 812 },  // 기준 해상도 — board 크기로 그대로 쓴다
};

// Penpot 형식 fill 헬퍼. figma 형식({type:"SOLID", color:{r,g,b}})은 인스턴스에서 막힌다.
const fill = (hex, opacity = 1) => [{ fillColor: hex, fillOpacity: opacity }];
```

### 토큰 출처
| 토큰 | 값 | 출처 (02 실측 / 03 적용 / 신규) | 비고 |
|---|---|---|---|

## D. 컴포넌트 스펙

| 컴포넌트 | 용도 | 크기·패딩 (토큰) | 타이포 | 색 (시맨틱) | 가변 부분 | 사용 화면 | 사용 횟수 |
|---|---|---|---|---|---|---|---|

## E. 컴포넌트 상태

| 컴포넌트 | Default | Hover | Active | Disabled | Error | Loading |
|---|---|---|---|---|---|---|
| Button/Primary | bg=brand, text=onBrand | … | … | bg=palette.gray200, text=text.disabled | border=danger + 하단 메시지 | 라벨→스피너, 입력 차단 |

## F. 반응형
- 기준 해상도: {width}×{height} (주 타깃: {PRD 근거})
- breakpoint 표 | 구간 | 폭 | 컬럼 | 좌우 여백 | 변화 규칙 |

## G. 말투 (Content tone) — 5·7단계가 문안을 쓸 때 그대로 따른다

> 포지션: {01 상단에서 그대로 옮겨 적는다 — 없으면 "01 미기재"}

| 항목 | 규칙 | 근거(02 실측 / design-copy-rules) |
|---|---|---|
| 종결 어미 | 안내문은 `~합니다`, 목록은 명사형 | |
| 버튼 라벨 | 동사형 2~4자 (`매수하기` 아니라 `매수`) | |
| 숫자·단위 | 천단위 쉼표, 단위는 붙여쓰기 | |
| 이모지 | 금지 / 허용 시 화면당 최대 개수와 02 근거 | |
| `—`·` - ` | 금지. 구분자는 `·` 또는 줄바꿈 | |
| 금지 표현 | "혁신적인", "완벽한", 3항목 병렬 나열 | |

### 카피 근거 (03 소구점 원장에서 인용 — 5·7단계가 변형해서 쓴다)

| 화면 유형 | 참고 C-id | 실제 문구(03에서 복사) | 이 문구에서 가져올 것(앵글·리듬, 그대로 베끼지 않는다) |
|---|---|---|---|

- 03의 원장이 비어 있으면 이 표도 비운다. **원장에 없는 문구를 지어내 이 표를 채우지 않는다.**

## H. 가정 (PRD에 답이 없어 정한 것)
| 항목 | 정한 값 | 이유 |
|---|---|---|
````

## 금지

- **`figma.variables.*` 로 토큰을 등록하라고 지시하지 않는다.** 토큰은 JS 상수로만 굴린다.
- 색을 figma 형식(`{type:"SOLID", color:{r,g,b}}`)으로 적지 않는다. **penpot 형식 HEX**로 적는다.
- 02에서 서버에 없다고 확인된 폰트를 토큰에 넣지 않는다.
- 값 없이 형용사만 적지 않는다. 모든 규칙은 **숫자 또는 토큰 이름**으로 끝나야 한다.
- 특정 PRD 전용 하드코딩 금지 — 위 코드블록의 값은 예시일 뿐, 매번 02·03에서 도출한다.
- 다른 단계의 출력 파일을 쓰지 않는다.
