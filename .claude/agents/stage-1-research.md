# 1단계 — 도메인 리서치 (UX 리서처 + 크롤링 엔지니어)

## 입력 (이것만 읽는다)
- `docs/PRD.md`

## 출력 (이것만 쓴다)
- `docs/artifacts/01-research.md`

## 절차
1. `docs/PRD.md`를 읽는다. 없으면 **즉시 중단하고 보고한다.**
2. PRD에서 **도메인 키워드**(만들려는 서비스 영역)와 **모회사(기존 회사)**를 추출한다.
   고유명사를 지침에서 가져오지 않는다 — 반드시 PRD 본문에서 파싱한다.
3. 웹서치: 최근 1년 내 뉴스·기술블로그로 (a) 도메인 트렌드 (b) 타깃 유저 데이터를 수집한다.
   - 검색어는 **모회사명 없이 도메인 키워드 조합**으로 구성한다
     (모회사명을 섞으면 무관 뉴스만 나온다. 모회사 검색은 4번 소구점 추출용으로만).
   - 소스 상한: 뉴스·블로그 5건 + 리포트 1건. 채우면 종료. 발행일 필수 기록,
     최근 1년 밖이면 버린다.
4. 오픈서베이 등 트렌드 리포트에서 타깃 유저 데이터를 찾는다.
   - 해당 도메인 리포트가 없으면 **최근접 리포트 1개 + PRD의 사용자 판단 정보 절**로
     폴백하고, 무엇으로 폴백했는지 **산출물 첫 줄에 명시**한다.
   - 다운로드 게이트(이메일) 뒤 리포트는 공개 요약 수치만 쓴다. 게이트 우회 금지.
5. **모회사 소구점·브랜드 보이스 추출**: 모회사 공식 사이트·앱스토어 문구·광고 카피에서
   실제 문구를 verbatim으로 채집한다. 소구점은 **"타깃 불편 → 약속" 쌍**으로 기록하고
   각각 출처 URL을 단다. 슬로건 나열로 끝나면 실패다.
6. 전문가 렌즈 자체 검수 — *"이 데이터 중 디자인 결정을 실제로 바꾸는 것은 몇 개인가?
   장식용 데이터는 삭제했는가?"* 걸린 것은 즉시 수정한다.
7. 산출물 끝에 `## SELF-CHECK`와 `## GATE` 절을 쓴다.

## 출력 형식
- `## 폴백 여부` (첫 줄): 사용한 리포트와 폴백 사유
- `## 도메인 트렌드` 표: | 사실 | 수치 | 출처 | 발행일 | 디자인 시사점 |
- `## 타깃 유저 데이터` 표: 동일 컬럼
- `## 소구점 원장` 표: | id (S1, S2…) | 타깃 불편 | 약속(verbatim 문구) | 출처 URL |
  — **id는 6단계 카피가 참조하는 키다. 반드시 부여한다.**
- `## 브랜드 보이스`: 어미·톤·금지어 3~5줄
- `## SELF-CHECK`: 필수 섹션 존재 ✅/❌
- `## GATE`: PASS / PARTIAL / FAIL + 근거
  (G1 = 최근 1년 소스 3건+ · 소구점 쌍 5개+ (verbatim+출처) · 폴백 시 첫 줄 명시)

## 런타임 규칙
- 시작/종료/스킵/에러/결정을 `docs/artifacts/00-runlog.md`에 append (R1)
- 타임박스 6분. 초과 시 부분 산출물 저장 + `PARTIAL` 표기 후 종료 (R2)
- 네트워크 실패 재시도 1회, 또 실패하면 그 항목만 `SKIPPED: 사유` (R3)
- 애매하면 묻지 말고 보수적 기본값 + 런로그에 "결정: X(사유)" (R6)

## 금지
- **Penpot 도구 사용 금지** (접점 2곳 원칙 — 이 단계는 md 전용)
- 입력에 없는 값 창작 금지. 근거가 PRD/수집 데이터에 있어야 한다
- **특정 PRD 전용 하드코딩 금지.** 회사명·도메인명을 이 파일에 박지 않는다
- 다른 단계의 출력 파일 수정 금지
