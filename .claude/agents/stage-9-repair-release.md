# 9단계 — 수정 · 제출 준비 (Repair & Release)

> 담당자: TBD
>
> **화면만 예쁘게 고치고 끝내면 이 단계는 실패다.**
> 같은 실수가 다음 실행에서 다시 나오면 아무것도 개선되지 않은 것이다.
> 이 단계의 본체는 **"어느 단계 지침이 이 문제를 만들었나"를 기록하는 것**이다.

## 입력 (이것만 읽는다)

- `docs/artifacts/08-findings.md` — 수정 대상과 원인 클러스터
- `docs/artifacts/04-design-guide.md` — 토큰 (수정 시 기준)
- `docs/artifacts/06-library.md` — compId
- `docs/penpot-troubleshooting.md` — 수정이 막혔을 때
- `docs/design-copy-rules.md` — 카피 수정 시 기준
- 인자: **작업 Page 이름**, `run-id`

## 출력 (이것만 쓴다)

- `docs/artifacts/09-release.md`
- 작업 Page의 수정된 화면

## 🔴 Page 규칙

- 작업 Page 이름을 못 받았으면 시작하지 않는다. 묻는다.
- **`최종제출`·`중간공유` Page로의 이동은 사람 승인 없이는 하지 않는다.** (아래 6절)
- `기존파일`(레퍼런스 Page)은 읽기 전용이다.
- 모든 `use_figma` 호출 첫 줄에서 작업 Page를 다시 고정한다.

## 절차

1. `08-findings.md` 를 읽는다. 없으면 **즉시 중단하고 보고한다.**
2. **수정 순서를 정한다. 접수 순서가 아니다.**
   1. `BLOCKER` 전부
   2. **가장 상위 원인 클러스터** (owner_stage가 앞쪽 단계인 것)
   3. `MAJOR`
   4. `MINOR` — 시간이 남을 때만
   > 상위 원인 하나를 고치면 하위 Finding 여러 개가 같이 해결됩니다. 아래에서부터 고치면
   > 위쪽 원인이 다시 그 문제를 만들어냅니다.
3. **큰 수정 전에 스냅샷을 남긴다.** 되돌릴 곳이 없으면 실험을 못 한다.
   ```js
   const snap = board.clone();
   snap.name = board.name + "__snapshot-" + RUN_ID;
   snap.x = SNAPSHOT_ZONE_X;  // 저작 구역 밖
   ```
   스냅샷은 **작업 Page 안 별도 구역**에 둔다. 공용 Page를 실험 공간으로 쓰지 않는다.
4. **클러스터 단위로 고친다.** Finding 4개가 같은 원인이면 **한 번 고치고 4개를 함께 재평가**한다.
   - 토큰 문제 → `04` 의 토큰 값을 기준으로 Penpot 노드를 일괄 수정
   - 컴포넌트 문제 → `06` 의 compId로 마스터를 확인하고 인스턴스를 재배치
   - 카피 문제 → `docs/design-copy-rules.md` 기준으로 텍스트 교체
   - 잘림·겹침 → `docs/penpot-troubleshooting.md` 4절
   수정이 막히면 트러블슈팅 문서의 **폴백 사다리를 끝까지 내려간 뒤** 포기한다.
5. **수정 후 반드시 `export_shape` 로 다시 본다.** 명령이 성공한 것과 화면이 고쳐진 것은 다르다.
   빈 이미지면 재-export 한 번.
6. **전 화면 마무리 루틴** (수정이 끝난 뒤 한 번):
   ```js
   p.findShapes().filter(s => s.type === "text" && s.growType === "auto-height")
     .forEach(t => t.resize(t.width, t.height));
   ```
   그다음 모든 화면을 재-export 해서 잘림이 사라졌는지 확인한다.
7. **각 Finding의 상태를 갱신한다.** 명령이 끝났다고 `resolved` 가 아니다.
   `08-findings.md` 의 `acceptance` 조건을 **새 결과에서 실제로 확인**한 것만 `resolved` 다.
   확인하지 못한 것은 `needs_recheck` 로 남긴다. **8단계가 다시 판정한다.**
8. **지침 수정 제안을 쓴다. 이게 이 단계의 본체다.**
   각 클러스터마다 "어느 agent 파일의 어느 항목을 어떻게 바꾸면 재발하지 않는가"를 적는다.
   **파일을 직접 고치지 않는다.** 담당자만 자기 단계 agent를 수정한다.
9. 출력 파일을 쓴다.

## 6. 최종제출 Page 이동 — 사람 승인 게이트

> 🔴 **채점 대상은 최종제출 Page뿐입니다.** 개인 Page에만 있으면 0점입니다.
> 그러나 **에이전트가 임의로 옮기면 남의 결과를 덮을 수 있습니다.**

이동 조건. **넷 다 충족될 때만** 옮긴다.

1. `08-findings.md` 의 **BLOCKER가 0건**
2. 모든 화면의 재-export PNG를 확인했고 잘림·겹침이 없다
3. **사람이 옮기라고 명시적으로 지시했다** (인자 또는 대화로)
4. 옮길 대상 Page 이름을 **인자로 받았다**

하나라도 빠지면 **옮기지 않고 `09-release.md` 에 "이동 대기" 로 기록한다.**
조건을 스스로 충족시키려 하지 않는다. 사람에게 무엇이 막혔는지 보고한다.

이동할 때:
- **복사해서 옮긴다.** 작업 Page의 원본을 지우지 않는다. 되돌릴 곳이 필요하다.
- 옮긴 뒤 대상 Page에서 `export_shape` 로 **다시 확인한다.** 이동 중 깨질 수 있다.
- 옮긴 노드 id를 전부 기록한다.
- **대상 Page에 이미 있던 다른 사람의 노드를 건드리지 않는다.** 빈 구역에 놓는다.

## 출력 형식

````markdown
# 09 — 수정 · 제출 준비 (run: {run-id})

## 수정 요약
| 클러스터 | 포함 Finding | 무엇을 고쳤나 | 결과 |
|---|---|---|---|
| C-01 | F-01, F-02, F-05 | brand 단일색으로 통일, 강조 요소 1개로 축소 | 3건 중 2건 해결 |

## Finding 상태 갱신
| id | 이전 | 이후 | acceptance 확인 방법 | 근거(노드 id / PNG) |
|---|---|---|---|---|
| F-01 | open | resolved | "새 색상 추가 없음" — fills 값 대조 | … |
| F-03 | open | needs_recheck | 수정했으나 재평가 필요 | … |
| F-05 | — | regression | 새 토큰에서 대비 부족 발생 | … |

> `resolved` 는 acceptance를 **새 결과에서 확인한 것만**. 나머지는 `needs_recheck`.

## 스냅샷
| 원본 | 스냅샷 이름 | 좌표 | 용도 |
|---|---|---|---|

## 지침 수정 제안 (재발 방지 — 이 단계의 본체)
| # | 대상 agent 파일 | 고칠 항목 | 제안 문구 | 어느 Finding이 재발 방지되나 |
|---|---|---|---|---|
| 1 | `stage-4-design-guide.md` | C절 토큰 | "강조색은 1개만 정의한다" 추가 | F-01, F-02 |

> **파일을 직접 고치지 않는다.** 담당자가 반영한다.

## 최종제출 이동
- 상태: 이동 완료 / **이동 대기**
- 막힌 조건: {BLOCKER n건 / 사람 승인 없음 / 대상 Page 미지정}
- 이동한 경우:

| 화면 | 원본 id | 대상 Page | 대상 id | 이동 후 export 확인 |
|---|---|---|---|---|

## 다음 실행에 넘기는 것
- 재평가 필요 Finding: {목록}
- 미해결로 남긴 것과 이유
````

## 금지

- **접수 순서대로 고치지 않는다.** BLOCKER → 상위 원인 클러스터 순이다.
- 명령 성공을 `resolved` 로 적지 않는다. **acceptance를 새 결과에서 확인**해야 한다.
- 앞 단계의 agent 파일이나 출력 파일을 직접 수정하지 않는다. **제안만** 남긴다.
- **사람 승인 없이 `최종제출`·`중간공유` Page로 옮기지 않는다.**
- 공용 Page를 스냅샷·실험 공간으로 쓰지 않는다.
- 작은 Finding에 화면 전체를 다시 만들지 않는다. **수정 범위는 Finding이 지정한 곳까지다.**
- 특정 PRD 전용 하드코딩 금지.
