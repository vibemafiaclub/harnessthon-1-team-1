# 10단계 — 업로드 한계점 분석

> 담당자: TBD
>
> **다음 회차가 이 파일 하나만 읽고 같은 함정을 피할 수 있어야 한다.** 그게 합격선이다.

## 입력 (이것만 읽는다)

- `docs/artifacts/05-html-review.md`
- `docs/artifacts/06-library.md` — "10단계로 넘기는 문제"
- `docs/artifacts/07-screens.md` — "10단계로 넘기는 문제", 커버리지 대조
- `docs/artifacts/09-release.md` — 수정 중 막힌 것
- `docs/penpot-troubleshooting.md` — **이미 알려진 함정인지 대조한다**
- 필요하면 Penpot을 **읽기만** 해서 현재 상태를 확인한다 (Page 전환·수정 금지)

## 출력 (이것만 쓴다)

- `docs/artifacts/10-limitations.md`

## 절차

1. 입력을 읽는다. 없으면 **즉시 중단하고 보고한다.**
2. 6·7·9단계가 넘긴 문제를 전부 모은다. 여기에 05가 찾은 가이드 충돌·PRD 누락 중
   **Penpot 저작에서 실제로 문제가 된 것**을 더한다.
2-1. **`docs/penpot-troubleshooting.md` 와 대조한다.**
   - 이미 그 문서에 있는 함정인데 또 걸렸다면 → **지침이 안 읽힌 것**이다. 어느 agent가
     그 문서를 참조하지 않았는지 6절에 적는다.
   - 그 문서에 **없는 새 함정**이면 → 6절에 "트러블슈팅 문서에 추가" 제안으로 적는다.
     이게 다음 회차가 같은 곳에서 안 막히게 하는 유일한 경로다.
3. 문제마다 **최소 분류**를 붙인다: `폰트` / `레이아웃` / `컴포넌트` / `인터랙션` / `이미지·자산` /
   `플러그인 API` / `협업(Page·이름 충돌)`. 분류에 안 맞으면 새로 만들고 이유를 적는다.
4. 각 문제를 **재현 가능하게** 적는다. "가끔 깨진다" 는 기록이 아니다.
   - 무엇을 실행했을 때 (스크립트 요지 또는 API 이름)
   - 무엇이 나왔는지 (에러 메시지 원문 / 조용히 대체된 결과)
   - 어느 노드에서 (board 이름 또는 id)
5. **개선 방법과 잔여 한계를 구분한다.**
   - 개선 방법: 이번에 실제로 통한 대응. 통하지 않았으면 "미해결" 이라고 적는다.
   - 잔여 한계: 대응 후에도 남는 것. **"없음"도 유효한 답이다.** 지어내지 않는다.
6. **되돌릴 것을 지정한다.** 문제 중 앞 단계 지침을 고치면 재발을 막을 수 있는 것은
   어느 agent 파일의 어느 항목을 고쳐야 하는지 적는다. (파일을 직접 고치지는 않는다.)
7. 출력 파일을 쓴다.

## 출력 형식

````markdown

## 요약

## 한계점 표

| 폰트 | 원본 폰트 미인식 | 줄바꿈 변경 | 서버 폰트 확인 후 대체 폰트 지정 | OS별 차이 가능 |
| 레이아웃 | … | … | … | … |
| 컴포넌트 | … | … | … | … |
| 인터랙션 | … | … | … | … |

> 위 4행은 **형식 예시**다. 실제로 발생한 것만 적는다. 발생하지 않았으면 그 행을 지운다.

## 재현 정보

## 앞 단계로 되돌릴 지침 수정 제안

> 참조하지 않았는지**를 위 지침 수정 제안에 적는다.
````

## 금지

- **겪지 않은 문제를 표에 채우지 않는다.** 위 예시 행을 그대로 남기는 것도 금지다.
  근거는 05/06/07 산출물 또는 실제 실행 로그에 있어야 한다.
- 앞 단계의 agent 파일이나 출력 파일을 수정하지 않는다. **제안만** 남긴다.
- Penpot을 수정하지 않는다. 읽기만 한다. Page 전환도 하지 않는다.
- 특정 PRD 전용 하드코딩 금지.
