# 3단계 — 경쟁사 분석 (프로덕트 디자이너 + 크롤러)

## 입력 (이것만 읽는다)
- `docs/PRD.md`

## 출력 (이것만 쓴다)
- `docs/artifacts/03-competitors.md`
- `docs/artifacts/images/` (수집 화면)

## 절차
1. PRD를 읽고 도메인을 파악한다. 없으면 즉시 중단·보고.
2. 경쟁 앱 선정 — 기준은 **활성 사용자 수 상위 3~5개**. 앱 이름을 지침에서 가져오지 않는다.
   MAU 데이터를 못 구하면 프록시로 폴백: 앱스토어 카테고리 랭킹 → 다운로드 수 → 언급량.
   어떤 지표/프록시를 썼는지 기록한다.
3. 화면 수집 — **폴백 사다리** (한 소스 실패 시 다음으로 자동 이동, 사용 소스 기록):
   ① uibowl.io → ② Mobbin 등 UI 레퍼런스 → ③ 앱스토어/플레이스토어 공식 스크린샷
   → ④ 공식 사이트·블로그·프레스킷 → ⑤ 유튜브 앱 리뷰 영상 프레임 캡처.
   전부 실패하면 이미지 없이 텍스트 리서치(리뷰·기사)로 플로우만 추출하고 그 사실을 명시한다.
   저장 후 파일 크기·포맷 확인 — 깨지면 재다운 1회, 실패 시 URL 링크로 대체.
4. 핵심 과업별 유저플로우 추출 — 형식 강제:
   **과업(유저 스토리) → 화면 시퀀스 → 각 화면의 결정적 UI 1개.**
   화면 나열로 끝나면 SELF-CHECK ❌.
5. **경쟁사 소구점 채집**: 앱당 온보딩·홈·핵심 과업 화면의 **실제 문구 verbatim 3개 이상**.
   id를 부여해 소구점 원장에 추가한다 (C1, C2…).
6. 전문가 렌즈 자체 검수 — *"이 플로우만 보고 화면을 그릴 수 있는가?
   화면 사이 전환 트리거가 다 있는가?"* 걸린 것은 즉시 수정.
7. `## SELF-CHECK` + `## GATE`.

## 출력 형식
- `## 선정` 표: | 앱 | 선정 지표(값) | 소스 |
- `## 유저플로우`: 과업별 — 화면 시퀀스(→ 연결) + 화면별 결정적 UI + 전환 트리거
- `## 소구점 원장(경쟁)` 표: | id (C1…) | 화면 | verbatim 문구 | 앵글 해석 |
- `## 수집 소스 기록`: 폴백 사다리 중 실제 사용한 소스
- `## SELF-CHECK`, `## GATE`
  (G3 = 앱 3~5개+지표 기록 · 과업→화면 시퀀스가 핵심 유저 스토리 수 이상 ·
   앱당 verbatim 3개+ · 화면 소스 기록)

## 런타임 규칙
- 런로그 append (R1) · 타임박스 6분 (R2) · 재시도 1회 후 항목만 SKIPPED (R3)
- 병렬 형제(1, 5a)와 독립 — 내 실패가 그들을 멈추지 않는다 (R4)

## 금지
- **Penpot 도구 사용 금지** (md 전용 구간)
- 특정 앱 이름·화면 개수 하드코딩 금지 (선정 "기준"만 지침에 남긴다)
- 로그인 월·게이트 우회 시도 금지
- 다른 단계의 출력 파일 수정 금지
