# 4단계 — 유저플로우 + 화면 인벤토리 (IA·인터랙션 디자이너)

## 입력 (이것만 읽는다)
- `docs/PRD.md`
- `docs/artifacts/02-persona.md`
- `docs/artifacts/03-competitors.md`

## 출력 (이것만 쓴다)
- `docs/artifacts/04-userflow.md`
- (필요 시) `docs/artifacts/feedback/02-feedback.md`, `03-feedback.md`

## 절차
1. 입력을 읽는다. `02`/`03` 한쪽이 PARTIAL이면 있는 쪽 + PRD로 진행하되 `저신뢰` 표기.
   **둘 다 부재면 PRD 단독 모드**(환원 규칙만으로) — 중단하지 않는다.
2. 소비자 검증: 02·03을 검사, 문제는 feedback 파일에 BLOCK/WARN 기록.
3. **포지션 문장 1개**를 산출물 첫 줄에 고정한다
   (모회사의 관점을 이 도메인에 이식하면 무엇이 달라지는가 — `01`의 보이스·소구점 근거).
4. **환원 규칙 4종**을 PRD 전 문장에 적용해 화면 목록을 도출한다:
   - "…결과를 확인" 문장 → 결과 화면
   - "…진입점" 필수 요소 → 그 목적지 화면
   - "정렬/필터 진입점" → 눌렀을 때 뜨는 시트
   - 사용자 상황 절의 빈 상태·로딩·실패 → 각 화면 1개씩
   각 화면에 **PRD 근거 문장 원문 인용**을 단다. 근거 없는 화면은 만들지 않는다.
5. 우선순위 부여: **P0**(PRD 명시 필수) / **P1**(환원 규칙 필수) / **P2**(확장).
   화면 20개+면 P2를 쳐낸다 — 저작 시간 초과 방지.
6. 플로우맵: 과업별 화면 시퀀스 + 전환 트리거. 각 플로우에 주 페르소나 표기.
   어느 페르소나도 안 쓰는 화면은 존재 이유를 적거나 삭제.
7. 전문가 렌즈 자체 검수 — *"이 화면을 지우면 어떤 유저 스토리가 끊기는가?
   답 못하는 화면은 P2로 강등하라."*
8. `## SELF-CHECK` + `## GATE`.

## 출력 형식
- 첫 줄: `> 포지션: {한 문장}`
- `## 환원 체크리스트` 표: | 규칙 | PRD 원문 인용 | 도출 화면 | 처리 |  (4종 전 행 처리)
- `## 화면 인벤토리` 표:
  | 화면명(`New/` 프리픽스) | P0/P1/P2 | PRD 근거 문장 | 포지션 반영 방식 | 주 페르소나 |
- `## 플로우맵`: 과업별 화면 시퀀스(→) + 전환 트리거
- `## SELF-CHECK`, `## GATE`
  (G4 = 환원 체크리스트 전 행 처리 · P0에 PRD 필수 화면 전부 ·
   전 화면에 근거+포지션+페르소나 컬럼 채움)

## 런타임 규칙
- 런로그 append (R1) · 타임박스 4분 (R2) · 질문 대신 보수적 기본값+기록 (R6)

## 금지
- **Penpot 도구 사용 금지** (md 전용 구간)
- "최소 N개" 목표 설정 금지 — 화면 수는 환원 규칙이 결정한다
- 경쟁사 플로우 통째 복사 금지 (포지션 반영 방식 컬럼이 공란이면 SELF-CHECK ❌)
- 특정 PRD 전용 화면명·개수 하드코딩 금지
- 다른 단계의 출력 파일 수정 금지
