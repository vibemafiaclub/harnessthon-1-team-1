# 3단계 — 경쟁사 조사

> 담당자: TBD

## 입력 (이것만 읽는다)

- `docs/PRD.md`

## 출력 (이것만 쓴다)

- `docs/artifacts/03-competitors.md`

## 절차

1. `docs/PRD.md` 를 읽어 **제품 카테고리와 핵심 과업**을 뽑는다.
   (예: "목록에서 항목을 훑고 → 상세에서 판단하고 → 그 자리에서 실행" 같은 흐름 단위로 적는다.)
2. 조사 대상을 **3~5개** 고른다. 선정 기준을 각각 한 줄로 적는다.
   - 같은 카테고리의 시장 1위 제품 1개 (기준선)
   - PRD가 지향하는 **톤**에 가까운 제품 1개 (PRD 배경 절에서 읽는다)
   - PRD가 지적한 **문제를 그대로 갖고 있는** 제품 1개 (반면교사)
   - 인접 카테고리에서 같은 과업을 잘 푸는 제품 1~2개
3. 각 제품에 대해 **아래 6항목을 전부** 채운다. 하나라도 비면 그 제품은 미완료다.
   - **정보구조** — 탭/네비 구성, 화면 계층, 무엇을 최상단에 올리는가
   - **핵심 사용자 흐름** — PRD의 핵심 과업을 이 제품은 몇 스텝에 끝내는가
   - **비주얼 아이덴티티** — 주조색·강조색 사용법, 타이포 위계, 밀도(빽빽함/여백)
   - **주요 컴포넌트** — 목록 행·카드·시트·필터·상태 표시 등의 생김새와 규칙
   - **강점** — 무엇이 잘 작동하는가
   - **약점** — PRD의 대상 사용자에게 무엇이 실패하는가
4. **판단을 내린다. 이게 이 단계의 본체다.** 관찰 항목마다 `적용` / `참고` / `제외` 중 하나와
   그 이유를 적는다. **판단 없는 관찰은 출력에 싣지 않는다.**
   - `적용` — 우리 디자인에 그대로 가져간다. **어느 화면·어느 컴포넌트에** 가져갈지 적는다.
   - `참고` — 아이디어만 빌리고 형태는 바꾼다. 무엇을 바꿀지 적는다.
   - `제외` — 쓰지 않는다. **PRD의 어느 문장과 충돌하는지** 적는다.
5. 근거 표기: 실제 조사(웹 검색·문서)로 확인한 것과 모델 지식으로 기술한 것을
   **`확인` / `추정`** 으로 구분해 표에 적는다. 스크린샷을 구하지 못하면 텍스트로 기술하되
   추정이라고 표시한다. **확인된 것처럼 쓰지 않는다.**
6. **화면(스크린샷) 수집은 폴백 사다리로 한다.** 한 소스가 막히면(로그인 월·결제벽·차단)
   우회하지 말고 다음으로 내려간다. 어떤 소스를 썼는지 출력에 기록한다.
   ① uibowl.io → ② Mobbin 등 UI 레퍼런스 → ③ **앱스토어/플레이스토어 공식 스크린샷**
   (iTunes Search/Lookup API `country=kr` — 리허설 실측에서 가장 안정적이었던 소스)
   → ④ 공식 사이트·블로그·프레스킷 → ⑤ 유튜브 리뷰 영상 프레임.
   전부 실패하면 텍스트 리서치(리뷰·기사)로만 기술하고 `추정` 표기. 저장한 이미지는
   `docs/artifacts/images/{제품}/`에 두고 크기·포맷을 확인한다(0바이트면 재다운 1회).
7. **소구점(카피)을 verbatim으로 채집한다.** 제품당 온보딩·홈·핵심 과업 화면의
   **실제 문구 3개 이상**을 그대로 인용하고 id(C1, C2…)를 부여한다.
   문구를 요약·의역하면 채집이 아니다. 이 원장은 뒤 저작 단계가 화면 카피를 쓸 때
   근거로 참조한다 — 원장이 없으면 AI 상투 문구("혁신적인"·"스마트한" 류)로 회귀한다.
8. 출력 파일을 쓴다.

## 금지

- 스크린샷 나열로 끝내지 않는다. **판단 표가 없으면 이 단계는 실패다.**
- 추정을 확인으로 표기하지 않는다.
- `적용 위치`를 앞 단계 산출물의 화면 ID로 적지 않는다. 이 단계는 1단계와 **병렬로 돌 수 있어서**
  01 산출물이 아직 없을 수 있다. **PRD가 쓴 화면 이름 또는 목적**으로 적는다.
- 특정 PRD 전용 하드코딩 금지 — 조사 대상은 매번 PRD에서 도출한다. 제품명을 이 파일에 박지 않는다.
- Penpot을 건드리지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
