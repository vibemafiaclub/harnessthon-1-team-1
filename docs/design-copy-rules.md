# 카피·표기 규칙 — "AI가 만든 티" 방어

> 이 파일이 **단일 원본**입니다. 콘텐츠를 만드는 단계(4·5·7)와 비평 단계(8)가 이 파일을 읽습니다.
> 규칙을 바꿀 때는 여기만 고칩니다.

심사는 "레퍼런스 회사가 실제로 만들 법한가"를 봅니다. AI가 쓴 문장은 **내용이 맞아도 어색해서**
그 판정을 깨뜨립니다. 아래는 판정 가능한 기준입니다. 취향이 아니라 **개수와 비율로 셉니다.**

---

## 1. 이모지 — 원칙적으로 쓰지 않는다

실제 모바일 앱 UI에서 이모지는 거의 쓰이지 않습니다. 아이콘이 그 자리를 대신합니다.
이모지가 보이면 그 화면은 즉시 "만든 티"가 납니다.

| 위치 | 허용 |
|---|---|
| 버튼·탭·내비게이션 라벨 | ❌ 금지 |
| 제목·섹션 헤더 | ❌ 금지 |
| 목록 행·카드 본문 | ❌ 금지 |
| 빈 상태 일러스트 자리 | ⚠️ 도형·아이콘으로 대체. 이모지로 때우지 않는다 |
| 사용자가 입력한 것으로 설정한 콘텐츠(채팅·리뷰·닉네임) | ✅ 자연스러운 범위에서 |

**정량 기준: 화면 1개당 이모지 0개.** 예외는 위 마지막 행뿐이고, 그 경우도 **화면당 2개 이하**입니다.
아이콘이 필요하면 도형으로 그리거나 아이콘 컴포넌트를 만듭니다.

**예외 조항**: 기존 자산 Page(레퍼런스)가 실제로 이모지를 쓰고 있다면 그 빈도까지는 허용합니다.
단 `02-existing-assets.md` 에 **실측 근거**가 있어야 합니다. 근거 없이 "이 브랜드는 캐주얼하니까"는 안 됩니다.

## 2. 하이픈·대시 — 문장 안에서 쓰지 않는다

한국어 UI에서 `—`(em dash)와 ` - `(공백 하이픈)은 거의 쓰이지 않습니다. AI 문체의 대표 신호입니다.

| 쓰려던 것 | 대신 |
|---|---|
| `삼성전자 — 반도체 대표주` | 줄바꿈으로 분리하거나 `삼성전자 · 반도체 대표주` |
| `오늘의 추천 - 변동성 선호` | `오늘의 추천` (제목) + `변동성 선호` (서브텍스트) |
| `빠르고 - 쉽게 - 안전하게` | 애초에 이 문장을 쓰지 않는다 (4번 참조) |
| 범위 표기 `1일-1개월` | `1일~1개월` 또는 `1일 · 1주 · 1개월` |

**정량 기준: 화면 1개당 `—` 0개, 문장 내 ` - ` 0개.**
구분자가 필요하면 **가운뎃점 `·`** 또는 **줄바꿈 + 폰트 위계**를 씁니다.
음수 부호(`-3.2%`), 날짜(`2026-08-01`), 전화번호는 하이픈이 아니라 기호이므로 해당 없습니다.

## 3. 문장 부호

- 느낌표: **화면당 1개 이하.** 광고 문구가 아닙니다.
- 물결표(`~`): 범위 표기 외 금지. `안녕하세요~` 금지.
- 말줄임(`...`): 실제로 잘린 텍스트에만. 여운 표현으로 쓰지 않습니다.
- 콜론 제목(`추천: 오늘의 종목`): 금지. 제목과 설명은 **위계로** 나눕니다.
- 괄호 부연 남발: 한 화면에 3개 이상이면 정보 구조가 잘못된 것입니다.

## 4. 문체 — AI가 반복하는 패턴

| 패턴 | 예 | 왜 티가 나나 |
|---|---|---|
| **3항목 병렬 강박** | "빠르고, 쉽고, 안전하게" | 실제 서비스는 하나만 말합니다 |
| **과잉 형용사** | "혁신적인", "완벽한", "최적의", "스마트한" | 근거 없는 자기 칭찬은 UI에 안 들어갑니다 |
| **모든 카드가 같은 길이** | 설명이 전부 18~20자 | 실제 데이터는 길이가 들쭉날쭉합니다 |
| **동일 어미 반복** | 모든 문장이 `~합니다` 또는 전부 `~하기` | 목록은 명사형, 안내는 종결형처럼 **역할별로** 나눕니다 |
| **자리표시자 잔존** | "여기에 설명", "제목1", "Lorem ipsum" | 즉시 미완성으로 보입니다 |
| **영어 혼용 남발** | "오늘의 Pick", "My 관심종목" | 레퍼런스가 실제로 그러는지 02에서 확인하고 따릅니다 |

**문장 길이 분산 기준**: 같은 목록 안 설명 텍스트의 글자 수가 **전부 ±2자 이내로 균일하면 실패**입니다.
최소 1개는 짧게, 최소 1개는 길게 (줄바꿈이 일어나는 것도 정상입니다).

## 5. 더미 데이터의 현실성

숫자가 예쁘면 가짜로 보입니다.

| 나쁨 | 좋음 |
|---|---|
| 1,000원 / 2,000원 / 3,000원 | 71,300원 / 8,450원 / 132,000원 |
| +1.0% / +2.0% / -1.0% | +2.34% / +0.18% / -1.07% |
| 모든 등락이 양수 | 상승·하락·보합이 섞여 있음 (보합 0.00%도 최소 1개) |
| 이름이 전부 2글자 | 길이가 다양하고, **최소 1개는 칸을 넘칠 만큼 길다** |

**긴 값을 반드시 1개 이상 넣습니다.** 말줄임 처리와 줄바꿈이 실제로 작동하는지는
긴 데이터가 있어야만 검증됩니다. 예쁜 데이터만 넣으면 심사 PRD에서 무너집니다.

## 6. 줄바꿈·간격 (기본 완성도)

- 한 줄에 들어가야 할 텍스트가 **두 줄로 넘어가 있지 않은가** — 넘어갔다면 폰트 크기나 칸 폭이 틀렸습니다.
- 두 줄이 정상인 텍스트가 **아래가 잘려 있지 않은가** — `growType = "auto-height"` 후 `resize` 재계산.
- 어절 중간에서 끊기지 않았는가.
- 같은 역할의 요소 사이 간격이 **전부 같은 토큰 값인가.** 17px, 18px 같은 비토큰 값이 있으면 실패.
- 목록 행의 좌우 여백이 화면 컨테이너 여백과 **일치하는가.**

## 검사 방법 (8단계 비평이 실행한다)

화면마다 아래를 **세어서** 기록합니다. 판정은 인상이 아니라 개수로 합니다.

| 검사 | 기준 | 결과 |
|---|---|---|
| 이모지 개수 | 0 (예외 조항 해당 시 ≤2 + 근거) | |
| `—` 개수 | 0 | |
| 문장 내 ` - ` 개수 | 0 | |
| 느낌표 개수 | ≤1 | |
| 자리표시자 텍스트 | 0 | |
| 목록 설명 글자수 분산 | 최댓값 − 최솟값 ≥ 5자 | |
| 반올림된 숫자 비율 | < 30% | |
| 비토큰 간격 값 | 0 | |

하나라도 어기면 `MINOR` 이상의 Finding입니다. 이모지·자리표시자는 `MAJOR` 입니다.
