# 페르소나 작성 기준 (정본: NN/g)

> 출처: https://www.nngroup.com/articles/persona/
> stage-2-persona agent가 이 파일을 로드해서 형식을 강제한다.

## 정의

허구적이지만 **현실적인** 전형적 사용자 설명. 구체적 사례가 일반화보다 기억에 남는다는
인간 특성을 이용해, 팀이 사용자에게 공감하고 디자인 결정의 근거로 쓰는 도구.

## 필수 필드 (페르소나 1명당)

| 필드 | 규칙 |
|---|---|
| 이름·나이·성별 | 기억성을 위한 것. 실존 인물 아님 |
| 직업·경험 수준 | 도메인 경험 수준 필수 (예: 투자 경험 0년) |
| 제품 사용 맥락 | 선택적 사용인가, 업무 필수인가 |
| 목표 | 이 제품으로 이루려는 것. **PRD 유저 스토리와 매핑** |
| 우려사항 | 막히는 지점·두려움. **PRD 상황 절과 매핑** |
| 태그라인 + 대표 인용구 | 1줄씩. 과하게 재치있게 쓰지 않는다 |
| **근거 출처** | 각 속성이 어느 리서치 데이터/PRD 문장에서 왔는지 표기 |

## 좋은 페르소나 조건

1. **사용자 조사 기반** — `01-research.md`의 실측 데이터에서 파생. 지어내지 않는다
2. **관련 디테일만** — "디자인 결정에 영향을 주지 않는 정보는 제거"
3. **기억성** — 이름·사진은 기억 강화용

## 금지 (흔한 실수)

- 과도하게 재치 있는 태그라인 (신뢰도 하락)
- 무관한 세부사항 과부하 (혈액형·취미 나열 금지)
- 근거 없는 속성 창작

## 파이프라인에서의 활용

- stage-4 (유저플로우): 화면 우선순위·"무엇을 위로 올릴지" 판단의 근거
- stage-6 (저작): 더미 데이터·카피를 페르소나 관점으로 작성
- stage-7 (검증): "이 페르소나가 이 화면에서 목표를 달성하는가" 리뷰 가이드
