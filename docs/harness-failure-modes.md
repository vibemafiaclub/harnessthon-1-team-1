# 단계별 실패 모드·무인 핸들링 정본

> ⚠️ **구조 매핑 노트 (2026-08-01)**: 이 문서는 구 7단계 구성안 기준으로 작성됐다.
> 현행 8단계 구조 매핑 — 구1 도메인리서치→stage-3·4에 분산 / 구2 페르소나→stage-4 /
> 구3 경쟁사→stage-3 / 구4 유저플로우·화면 인벤토리→stage-1 / 구5a 토큰실측→stage-2 /
> 구5b·6 저작→stage-6·7 / 구7 verify→stage-verify-penpot.
> 원칙(R1~R8 런타임 규칙·GATE 게이트·Penpot 접점 2곳·소구점 원장)은 구조와 무관하게 유효하다.


> 전제: 하네스는 **20~30분 무인 실행**된다. 실행 중 사람에게 물어볼 수 없다.
> 따라서 모든 필수 인자(작업 Page 이름 등)는 **시작 전에** 확보하고, 실행 중 오류는
> 아래 규칙으로 자동 처리한다. 각 stage agent 본문에 해당 단계 표를 그대로 넣는다.

| 실패 모드 | 감지 | 핸들링 |

| 색 추출 노이즈 (수십 색) | 색 개수 | 사용 빈도 상위 색만 시멘틱 매핑(primary/신호색/중립 스케일). 나머지는 부록 |
| `figma.variables.*` 사용 | — | 금지. 토큰은 JS 상수 + `05a-tokens.md`. (성공 응답만 오고 안 남는 함정) |
| 읽기 중 Page 전환으로 팀원 화면 바뀜 | — | **읽기만 할 때는 Page 전환하지 않는다** (노드 트리 접근으로 읽기) |

## 6단계 — 화면 저작 (시니어 프로덕트 디자이너 시점)

| 실패 모드 | 감지 | 핸들링 |
|---|---|---|
| 안 보고 쌓기 → 마지막에 전부 어긋남 | — | 화면 1개 완료마다 `export_shape` PNG 확인. 빈 영역이면 **재-export 1회** 후 판단 (레이아웃 안정 전 캡처 함정) |

| 고정 폭 텍스트 잘림 | PNG 검수 | `growType="fixed"` 금지 → `auto-height` |
| 비-오토레이아웃 프레임 `appendChild` 자식 안 옮겨짐 | 좌표 확인 | 붙인 뒤 `c.x/c.y` 수동 보정 |
| 반투명 스크림 렌더에서 사라짐 | PNG 검수 | 스크림 대신 **뒤 보드 `opacity`를 낮춤** |

| AI티 카피 회귀 (소구점 원장 무시) | 출처 컬럼 공란 | 화면 내 모든 문구는 `01`·`03` 소구점 원장 참조 id 표기. 참조 없는 문구는 verify에서 FAIL 사유 |
| 상태 화면을 처음부터 다시 지음 | — | 기본 화면 `clone()` → 덮을 것만 교체 (모달·에러·로딩·빈 상태) |

## 7단계 — verify (QA 시점)

| 실패 모드 | 감지 | 핸들링 |
|---|---|---|
| 관대한 자기 채점 ("대체로 좋음") | — | 서술 금지. **기계적 대조만**: `04`의 화면 목록 × Penpot board 이름 1:1 매칭 표, PASS/FAIL 이진 판정 |
| 재실행 무한 루프 | 재시도 카운트 | FAIL 단계 재실행은 **1회만**. 그래도 FAIL이면 무엇이 왜 비었는지 런로그·99-verify에 남기고 종료 |
| verify 자신이 저작 Page를 오염 | — | verify는 **읽기 전용**. 어떤 노드도 만들거나 수정하지 않는다 |
| PARTIAL 산출물을 PASS 처리 | PARTIAL 태그 | PARTIAL이 하나라도 있으면 전체 판정은 `PARTIAL PASS` — 완료 선언 금지, 남은 작업 목록 출력 |
