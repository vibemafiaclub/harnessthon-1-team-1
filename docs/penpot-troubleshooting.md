# Penpot 결과가 안 나올 때 — 진단과 폴백

> 이 파일이 **단일 원본**입니다. 저작 단계(6·7)와 검증 단계가 막혔을 때 이 파일을 읽습니다.
> "안 된다"고 보고하기 전에 **여기 있는 사다리를 끝까지 내려간 뒤에** 보고합니다.

Penpot 저작은 두 가지로 실패합니다. **먼저 어느 쪽인지 가릅니다.**

| | 증상 | 어디로 |
|---|---|---|
| **A. 안 만들어진다** | 에러가 나거나, 성공 응답인데 화면에 없다 | ↓ 1~3절 |
| **B. 만들어졌는데 형편없다** | 도형은 있는데 잘리고 겹치고 어긋난다 | ↓ 4절 |

---

## 0. 막히면 제일 먼저 — 3줄 점검

거의 모든 "안 된다"는 이 셋 중 하나입니다.

```js
// 매 use_figma 호출 첫 줄. 예외 없다.
const PAGE = "{작업 Page 이름}";
const p = penpot.currentFile.pages.find(x => x.name === PAGE);
if (!p) return { error: "page not found: " + PAGE, pages: penpot.currentFile.pages.map(x => x.name) };
penpot.openPage(p);
```

1. **Page를 다시 고정했는가.** `openPage()` 는 **다음 호출까지 유지되지 않습니다.** 이걸 빼먹으면
   엉뚱한 Page에 그려지고, 내 Page를 보면서 "안 만들어졌다"고 판단하게 됩니다.
2. **전환한 그 호출에서 새 노드를 만졌는가.** Page를 막 전환한 호출 안에서 그 Page의 새 노드를
   만들면 죽습니다. **전환만 하는 호출**을 따로 한 번 보내고, 다음 호출부터 저작합니다.
3. **한 호출에 너무 많이 넣었는가.** 실패 지점을 알 수 없게 됩니다. 화면 1개 = 호출 3~5개로 쪼갭니다.

## 1. 연결 자체가 안 될 때

| 증상 | 원인 | 대응 |
|---|---|---|
| plugin 패널이 비어 있음 | iframe 로딩 전 | 몇 초 기다린다. Connect UI가 뜨는지 본다 |
| MCP 도구가 CLI에 안 보임 | MCP 서버 미실행 | MCP 터미널이 살아 있는지 확인. **행사 중 계속 켜 둔다** |
| `EADDRINUSE` | 서버를 두 번 실행 | 새로 띄우지 말고 **기존 터미널을 찾아 그대로 쓴다** |
| 중간에 연결이 끊김 | 브라우저 탭 또는 터미널 종료 | 둘 다 유지. 재연결 후 **Page 고정부터 다시** |
| 레퍼런스를 못 읽음 | plugin은 **열려 있는 파일 밖을 못 본다** | 대상 Page가 같은 파일에 있는지 확인. 다른 파일이면 읽을 수 없다 — 보고한다 |
| local plugin 주소를 브라우저 탭에서 직접 엶 | 그 탭이 연결을 가로챈다 | 탭을 닫고 **Penpot 내부 plugin 설치 흐름**에서 연다 |

**저작 전 preflight**: 작업 Page에 사각형 1개를 만들고 → `export_shape` 로 보이는지 확인 → 지웁니다.
이게 안 되면 그 뒤의 모든 작업은 무의미합니다. **preflight 실패 시 저작을 시작하지 않고 보고합니다.**

## 2. 호출은 성공했는데 결과가 없을 때

| 증상 | 원인 | 대응 |
|---|---|---|
| `figma.*` 호출이 에러 | 미지원 API | 에러 메시지를 읽고 **`penpot.*` 로 대체**한다. 에러는 명확하게 안내된다 |
| `figma.variables.*` 가 성공하는데 토큰이 없음 | 실제로 남지 않는다 | **쓰지 않는다.** 토큰은 JS 상수 객체로 굴린다 |
| `primaryAxisSizingMode` 등이 무시됨 | figma 사이징 프로퍼티 미지원 | `node.horizontalSizing = "fix" \| "auto"` |
| 폰트가 조용히 바뀜 | 서버에 없는 폰트 (**에러가 안 난다**) | `penpot.fonts.all` 로 먼저 확인하고 대체 폰트를 정한다 |
| `appendChild` 했는데 자식이 안 옮겨짐 | 비-오토레이아웃 프레임 | 붙인 뒤 `c.x = parent.x + dx; c.y = parent.y + dy` 로 직접 배치 |
| 컴포넌트를 이름으로 찾았는데 엉뚱한 게 잡힘 | **컴포넌트 이름은 파일 전역** | `06-library.md` 에 기록한 **compId** 로 찾는다 |
| 이름 바꾸거나 자식 지운 뒤 플러그인이 멈춤 | 지원되지 않는 조작 | 되돌리려 하지 말고 **새 이름으로 새로** 만든다 |
| `export_shape` 가 빈 이미지 | 레이아웃 안정 전에 찍힘 | **재-export 한 번.** 그래도 비면 그때 문제로 본다 |

## 3. 그래도 안 될 때 — 폴백 사다리

**위에서부터 내려갑니다. 한 칸 실패했다고 포기하지 않습니다.**

1. **쪼갠다** — 실패한 호출을 절반으로 나눠 어느 쪽이 죽는지 찾는다.
2. **API를 바꾼다** — `figma.*` → `penpot.*`, 또는 그 반대.
3. **구조를 낮춘다** — 오토레이아웃이 말썽이면 **고정 좌표**로 배치한다.
   (완벽한 auto layout보다 **보이는 화면**이 먼저다.)
4. **컴포넌트를 포기하고 인스턴스 대신 clone** — `shape.clone()` 은 안정적으로 동작한다.
   재사용 점수는 잃지만 화면은 남는다.
5. **해당 요소만 건너뛴다** — 화면 전체를 포기하지 않는다. 빠진 요소를 기록하고 나머지를 완성한다.
6. **기록하고 보고한다** — 여기까지 왔으면 `10-limitations.md` 에 재현 정보와 함께 남긴다.

> **화면 0개보다 불완전한 화면이 낫습니다.** 채점은 최종 Page에 있는 것으로만 합니다.
> 완벽한 구조를 만들려다 시간을 다 쓰면 아무것도 남지 않습니다.

## 4. 만들어졌는데 결과가 나쁠 때

이쪽이 실제로 더 자주 점수를 깎습니다. **증상별 원인이 정해져 있습니다.**

| 보이는 증상 | 원인 | 대응 |
|---|---|---|
| 텍스트 아래가 잘림 | hHug 프레임 안에서 굳음 | 전 화면 저작 후 `growType==="auto-height"` 텍스트를 전부 `resize` 로 재계산 |
| 고정 폭 텍스트가 잘림 | `growType = "fixed"` | `"auto-height"` 로 바꾼다 |
| 텍스트를 갈아끼웠더니 위치가 어긋남 | hug(자동 폭) 칸 | **고정 폭 + 텍스트 정렬**로 바꾼다 |
| 하단 고정 요소가 위로 올라붙음 | `layoutGrow` Spacer가 폭 1로 되돌아감 | Spacer **높이를 계산해서 명시**한다 |
| 모달 뒤 스크림이 안 보임 | 반투명 오버레이가 렌더링에서 사라짐 | 스크림을 덮지 말고 **뒤 화면 board의 `opacity`** 를 낮춘다 |
| 인스턴스 색이 안 바뀜 | figma 형식 `fills` 를 씀 | penpot 형식 `[{fillColor:"#RRGGBB", fillOpacity:1}]` |
| 자식 순서가 뒤죽박죽 | 추가 순서 문제 | `board.insertChild(index, node)` (지우기보다 안전) |
| 요소가 겹침 | 좌표 계산 누락 | 배치 구역을 표로 먼저 정하고 계산해서 넣는다 |
| 전체가 휑함 | 콘텐츠 부족 | 목록 행 수를 늘린다. `design-copy-rules.md` 5절의 현실적 더미 기준을 따른다 |

## 5. 시간이 부족할 때 — 무엇을 버리는가

**버리는 순서가 정해져 있습니다.** 아래에서 위로 버립니다.

| 우선순위 | 항목 | 버려도 되나 |
|---|---|---|
| 1 (절대 사수) | **최종 Page에 P0 화면이 존재** | ❌ |
| 2 | 텍스트 잘림·겹침 없음 (기본 완성도) | ❌ |
| 3 | 토큰 일관성 (색·간격) | ❌ |
| 4 | 상태 화면 (빈/로딩/에러) | ⚠️ P1부터 버린다 |
| 5 | 컴포넌트 인스턴스화 | ⚠️ clone으로 대체 가능 |
| 6 | 프로토타입 연결 | ✅ 미지원이면 포기하고 기록 |
| 7 | 반응형 변형(태블릿·데스크톱) | ✅ 기준 해상도만 남긴다 |

**막판 10분에는 새로 만들지 않습니다.** 저장 · 결과 Page 확인 · 잘린 텍스트 재계산만 합니다.
