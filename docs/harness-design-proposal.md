# 하네스 구성안 (제안: 최병찬)

> 팀 sync용 제안 문서. 확정되면 조장이 `/scaffold-harness`에 이 단계 목록을 넣어 실행한다.
> 원칙: AGENTS.md 준수 — 단계=sub agent 1개=산출물 1개, 파일로만 통신, 반하드코딩.

## 설계 사상

**유저플로우가 심장이다.** PRD 핵심 유저 스토리(3절)를 리서치·페르소나·경쟁사 플로우로
뒷받침해서 화면 인벤토리를 도출하고, 디자인 시스템은 기존 자산 실측으로 만든다.
"최소 N개" 목표가 아니라 **환원 규칙**으로 화면 개수가 결정되게 한다.

```
[1 리서치] ──┐
             ├→ [2 페르소나] ──┐
[3 경쟁사] ──┘                 ├→ [4 유저플로우/화면 인벤토리] → [6 화면 저작] → [7 검증]
[5a 토큰 실측(병렬)] ──────────┴→ [5b 컴포넌트 저작] ──────────┘
```

## 단계 정의

| # | 단계 | 입력 | 출력 | 병렬 |
|---|---|---|---|---|
| 1 | **도메인 리서치** — PRD에서 도메인·목표 서비스 추출 → 최근 1년 뉴스·기술블로그 웹서치 + 오픈서베이 트렌드리포트에서 타겟 유저 데이터 수집. **기존 회사(모회사)의 소구점·브랜드 보이스도 추출** | `docs/PRD.md` | `01-research.md` | 3, 5a와 병렬 |
| 2 | **페르소나** — NN/g 기준(이름·나이·직업·사용맥락·목표·우려·인용구)으로 2~3명. 근거는 1의 리서치 데이터 + PRD 유저 스토리. 디자인 결정에 영향 없는 디테일 금지 | PRD + `01` | `02-persona.md` | — |
| 3 | **경쟁사 분석** — 기준: 활성 사용자 수 상위 3~5개 앱. uibowl.io 등에서 화면 수집 → 핵심 과업별 유저플로우 + **경쟁사 소구점(카피 앵글·문구 실측)** 추출 | `docs/PRD.md` | `03-competitors.md` + `docs/artifacts/images/` | 1, 5a와 병렬 |
| 4 | **유저플로우 + 화면 인벤토리** — PRD 유저 스토리 × 페르소나 × 경쟁사 플로우 → 화면 목록(근거 문장 필수) + 플로우맵. 우리 포지션(예: 당근이면 "내 주변" 관점) 명시. 빈/로딩/실패 상태 화면 포함 | PRD + `02` + `03` | `04-userflow.md` | — |
| 5a | **디자인 토큰 실측** — Penpot `기존파일` Page를 읽어 색·타이포·간격·반경 실측 → 시멘틱 토큰(JS 상수). 구조는 MUI/Material 시멘틱 패턴(`primary.main/light/dark/contrastText`, spacing(1)=8px 등) | Penpot `기존파일` | `05a-tokens.md` | 1, 3과 병렬 |
| 5b | **컴포넌트 저작** — `04`의 화면 인벤토리에서 필요 컴포넌트 역산(버튼·토글·리스트행·칩·시트 등). Vibe Dictionary 분류로 명명, Material 상태값(enabled/pressed/disabled + 정보 변형) 포함해 Penpot에 컴포넌트로 제작 | `04` + `05a` | `05b-components.md` + Penpot 컴포넌트 | — |

## 단계별 반하드코딩 규칙 (agent 본문에 박을 것)

- **1 리서치**: 도메인 키워드는 PRD에서 추출한다. "증권"·"당근"을 지침에 박지 않는다.
  오픈서베이에 도메인 직접 리포트가 없으면 → 최근접 리포트 + PRD 4절(판단 정보)로 폴백하고,
  무엇으로 폴백했는지 산출물에 명시한다. (당근 리허설 실측: 금융 리포트 없음 → "결제 서비스 2026"이 최근접)
- **2 페르소나**: 리서치/PRD에 근거 없는 속성을 지어내지 않는다. 각 필드에 근거 출처를 단다.
  과한 태그라인·무관 디테일 금지(NN/g).
- **3 경쟁사**: "상위 3~5개" 기준은 앱 이름이 아니라 선정 기준(활성 사용자 수)으로 지침에 쓴다.
  **화면 소스 폴백 사다리** — 한 소스가 접속 불가·차단이면 다음으로 자동 이동, 어떤 소스를
  썼는지 산출물에 기록: ① uibowl.io → ② Mobbin 등 UI 레퍼런스 사이트 → ③ 앱스토어/플레이스토어
  공식 스크린샷 → ④ 공식 사이트·블로그·프레스킷 → ⑤ 유튜브 앱 리뷰 영상 프레임 캡처.
  전부 실패하면 이미지 없이 텍스트 리서치(리뷰·기사)로 유저플로우만 추출하고 그 사실을 명시.
- **4 유저플로우**: 화면 환원 규칙 — "결과 확인" 문장→결과 화면, "진입점"→목적지 화면,
  "정렬/필터 진입점"→시트, 상황 절의 빈/로딩/실패→화면 하나씩.
- **5**: 토큰 값을 지침에 박지 않는다. 실측 절차만 쓴다. `figma.variables.*` 금지(JS 상수로).
  fills는 penpot 형식 `{fillColor:"#RRGGBB"}`.
- **6**: 작업 Page 이름은 인자. 없으면 묻고 시작하지 않는다. 작게 실행+PNG 확인 반복.
- **6 카피(AI티 방지)**: 화면 안 문구는 지어내지 않는다. `01`(기존 회사 소구점·보이스) +
  `03`(경쟁사 소구점 실측)의 **소구점 원장에서만 도출**하고, 어느 소구점에서 왔는지 표기.
  AI 상투 문구("혁신적인", "스마트한", "당신만을 위한" 류) 금지. 톤앤매너는 기존 회사 보이스 우선
  (PRD 7절 "기존 디자인의 톤앤매너 유지"와 동일 원칙의 카피 버전).
